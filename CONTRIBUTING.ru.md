# Участие в разработке Civis

Прежде всего, спасибо, что рассматриваете возможность участия в разработке Civis! Именно такие люди, как вы, делают Civis отличным сообществом.

## Кодекс поведения

Участвуя в этом проекте, вы соглашаетесь соблюдать [Кодекс поведения участника](https://www.contributor-covenant.org/ru/version/2/0/code_of_conduct/).

## Как я могу помочь?

### Сообщение об ошибках

- Проверьте, не сообщали ли уже об этой ошибке в [Issues](https://github.com/LeonidYasin/civis/issues)
- Если нет, создайте новую задачу с:
  - Чётким заголовком и описанием
  - Шагами для воспроизведения
  - Ожидаемым и фактическим поведением
  - Скриншотами или логами, если применимо

### Предложение улучшений

- Создайте задачу с меткой `enhancement`
- Опишите функцию и почему она будет полезна
- Приложите примеры или макеты, если возможно

### Pull Requests

1. Сделайте форк репозитория
2. Создайте новую ветку: `git checkout -b feature/название-вашей-функции`
3. Внесите изменения
4. Запустите тесты, если они есть
5. Сделайте коммит с понятным сообщением: `git commit -m "feat: добавить что-то"`
6. Отправьте изменения в ваш форк: `git push origin feature/название-вашей-функции`
7. Откройте Pull Request

## Настройка окружения для разработки

```bash
# Клонирование вашего форка
git clone https://github.com/ваше-имя-пользователя/civis.git
cd civis

# Установка зависимостей
pip install -r requirements.txt

# Копирование .env файла
cp civis_bot/.env.example civis_bot/.env

# Запуск бота локально
cd civis_bot
python bot.py
```

## Руководство по коду

- Следуйте [PEP 8](https://peps.python.org/pep-0008/) для Python кода
- Используйте осмысленные имена переменных
- Добавляйте комментарии для сложной логики
- Делайте функции небольшими и сфокусированными
- Обновляйте документацию при изменении функций

## Формат коммитов

Используйте [Conventional Commits](https://www.conventionalcommits.org/):

- `feat:` — новая функция
- `fix:` — исправление ошибки
- `docs:` — обновление документации
- `style:` — форматирование (без изменения кода)
- `refactor:` — рефакторинг кода
- `test:` — добавление тестов
- `chore:` — задачи по обслуживанию

Пример: `feat: добавить команду /support для обратной связи`

## Стиль оформления

- **Python**: отступы 4 пробела, максимальная длина строки 120 символов
- **Markdown**: по возможности не превышайте 80 символов в строке
- **SQL**: используйте ЗАГЛАВНЫЕ БУКВЫ для ключевых слов

## Тестирование

В настоящее время тесты ограничены. Если вы добавляете функцию, пожалуйста, также добавьте тесты.

## Документация

- Обновите `README.md` для изменений, видимых пользователю
- Обновите `README.ru.md` для русской версии
- Обновите `CHANGELOG.md` для новых функций и исправлений
- Добавляйте комментарии в код для новых функций
